# コード進行構文の定義（v1）

## 入力表記と構造化された表現

括弧付きの拡張指定と、後述する省略記法の両方を受理します。
`plain` は空白を除去した入力表記と拡張指定の順序を保持し、formatter もその表記を出力します。
`detailed.extensions` は後述の固定順序に並べます。重複の削除や構成音の補完は行いません。
`C7sus4` と `Csus4(7)` の detailed は同じですが、plain と AST 全体は異なります。

0.x から 1.0.0 への更新時は、保存した原文から AST を再生成してください。拡張指定の順序が異なる
旧 AST は formatter の round-trip 検証で拒否される場合があります。順序に依存する派生データも
再生成し、追加された `omit5` に合わせて extension の網羅的な分岐を更新してください。
AST だけを保存している場合は、更新前の formatter で文字列を書き出しておいてください。

## 例

```txt
@section=SimpleVerse
C - Dm - Em - F
G - Am - Bm(o) - C

@section=ComplexChorus
[key=Gm]F(9,13) - Fm(6) - Bb(add9,13) - Bbaug
[key=E]F#m(b5,7),Gm(M9) - Bm(7,9) - E(M13) - Edim
```

## 構文

- 基本
  - 厳密な文法は [chord-progression.ebnf](../chord-progression.ebnf) を参照
  - [generatedTypes.ts](../../resources/generatedTypes.ts)を参照
- 詳細
  - `SectionMeta`
    - 形式：`@key=value`
    - `@section=名前`：セクション名
    - `@repeat=2`：繰り返し回数
    - `@same=名前`：指定セクションと同じコード進行であることを示す参照
  - `ChordInfo`
    - 形式：`[key=value]Chord`。コードには省略記法と末尾の括弧付き拡張指定を使えます
    - 捕捉：
      - `[key=value]`　・・・オプショナル
      - `(extension)`　・・・オプショナル。extensionはカンマ区切りで複数指定可能
      - `Chord`　・・・`C/B`のような分数コード、`?`、`%`, `_`も可能
        - `?` ・・・ 不明
        - `%` ・・・ 前のコードと同じ
        - `_` ・・・ コードなし
  - 区切り
    - `C-D` ・・・ `C`と`D`を別々のbarとして扱う
    - `C,D` ・・・ `C`と`D`を同じbarとして扱う
    - 1個の改行 ・・・ 同じsection内の改行として扱う
    - コード行の間の空行 ・・・ 同じsection内の空行として保持する。複数の空行は1行へまとめる（ASTでは`br`を2個並べる）
    - 空行でsection名・key・`%`の前コード参照をリセットしない
    - コード行の後のsection metaも新しいsectionを開始する（改行は1個でも可）
    - 最初のコード行より前の空行ではsectionを分割せず、先行するsection metaを保持する
    - 文書の先頭・末尾と、sectionの最初のコード行より前の改行・空行は省略する
  - 制約
    - chord metaは対象chordの直前に置く。`C[key=A]`のような後置は不可
    - section metaは専用行に置く
    - pipeを使う`|C|`記法には対応しない

## セクション名

`@section=`と`@same=`の値は、行末（LF・CRLF・CR）または入力末尾までの自由文字列です。
ハイフン・空白・タブ・括弧・スラッシュ・`=`・`@`・Unicode文字を名前に使えます。
前後の半角空白とタブは除き、名前の途中の空白や記号、大文字・小文字はそのまま保持します。
空の名前は`SMIV-1`エラーです。名前自体に改行は含められません。

```txt
@section=pre-chorus / サビ前 (2)
C - G

@same=pre-chorus / サビ前 (2)
```

同じ行の`@repeat=2`なども名前の一部になります。別のメタ情報やコード本文は必ず次の行へ記述してください。
引用符やコメントの特別な解釈はありません。`@repeat`は自由文字列ではなく、従来どおり0以上の整数です。

## セクションの参照（`@same`）

```txt
@section=Verse
C - G - Am - F

@section=Reprise
@same=Verse
@repeat=2
```

参照側の名前は`@same`より前の`@section`で指定できます。名前は省略できます。
ASTでは`SectionMeta`の`{ "type": "same", "value": "Verse" }`として参照名を保持し、
参照先のコード進行へ展開しません。参照だけのセクションの`chordBlocks`は空配列です。
参照名は`@section`と同じ行末までの自由文字列として読み取り、Unicodeや大文字・小文字を保持します。

`@same`の後の`@repeat`はその参照側に属します。後続の`@section`や`@same`は、
コード本文がなくても新しいセクションを開始します。

`@same`はセクション全体の参照です。同じセクションにコード本文を併記すると
`SMIV-4`の構文エラーになります。本文を記述する場合は、次の`@section`で
新しいセクションを開始してください。

参照先の存在確認、前方参照・自己参照・循環参照の扱い、同じ名前で内容が異なる
セクションからどれを選ぶかはアプリケーション側が決定します。パーサーは先頭の候補を
採用するなどの解決を行わず、指定と定義を入力順に保持します。

## スラッシュコードの分母

分母は音名またはコード本体と同じ文法で記述します。`C/G`、`C/F#`、
`C/F#m(7,b5)`を受理し、分母の表記をASTの`denominator`へ文字列として保持します。
`C/?`はコードがC、ベース音が不明であることを表します。`?`は分母全体としてのみ使えます。

`C/5`、`C/Unknown`、`C/Garbage`、`C/%`、`C/_`などは`DEN-1`エラーです。
分母も同じ省略記法を使えます。`C/G7`、`C/F#m7b5`、`C/Gsus4(7)`も有効です。
構造記号の前後には空白を置けますが、`C/G m`のように音名とコード種別を分割できません。

## エラー・警告の位置

`lineNumber` は1始まりの行番号、`columnNumber` は行内の Unicode スカラー値を
数えた1始まりの列番号です。タブも1文字として数えます。`length` もスカラー値の
個数であり、UTF-8 のバイト数・UTF-16 の長さ・見た目の文字数とは異なります。

`startOffset` と `endOffset` は元の入力に対する0始まりの UTF-16 offset で、
終了位置は範囲に含みません。例えば不正なコード `H😀` は `length: 2`、範囲は
`[0, 3)` です。JavaScript では `input.slice(startOffset, endOffset)` で
該当する文字列を取得できます。Rust の文字列スライスに必要なバイト位置とは異なります。
EOF のエラーは長さ0の範囲です。CRLF は1個の改行ですが、スカラー値と UTF-16 の長さは2です。

## 重複指定の警告

`C(9,9)` は有効な表記として受理し、AST の重複も保持します。同じコードの
拡張指定で、括弧の内外を通して同一の値が2回以上出現すると、2個目以降それぞれに
`DUPLICATE_EXTENSION` の警告を付けます。`9` と `add9` などの音楽的な意味の
重複は判定しません。

JavaScript API は成功・失敗のどちらにも `warnings` 配列を返します。
警告だけでは解析に失敗せず、警告がなければ空配列になります。警告の位置は
元の入力に対するもので、エラーと同じ行・列および UTF-16 offset を使います。
構文エラーを含むコードで検出した重複も警告として返しますが、拡張指定を許さない
`%`・`_`・`?` や、スラッシュ分母内の拡張指定は警告の対象にしません。

各 npm パッケージの `warning_code_message_map` サブモジュールから
`getWarningMessage({ warningCode: warning.code, lang: "ja" })` を使って
表示用メッセージを取得できます。`lang` は `"ja"` または `"en"` です。
Node.js の ESM またはブラウザから直接 import する場合は `.js` を付けます。

[`Extension`](../../resources/generatedTypes.ts) enum と一致します。

<!-- extension-values:end -->

コード本体の後ろには、空でない括弧のグループを1つまで置けます。
括弧内ではすべての extension を指定でき、複数の値はカンマで区切ります。
コード種別の `m`、`M`、`aug`、`dim` は extension ではなく、コード本体に記述します。

括弧外では、先頭に数字系の指定を1つまで置けます。
対象は `1`、`2`、`3`、`4`、`5`、`6`、`7`、`9`、`11`、`13`、`M7`、`M9`、`M11`、`M13` です。
その後には `sus2`、`sus4`、`add9`、`add11`、`add13`、`b3`、`b5`、`#5`、`b6`、
`b9`、`#9`、`b11`、`#11`、`b13`、`#13`、`omit5` を複数続けられます。
括弧外で数字系の指定をほかの拡張指定の後に置くことはできません。
長いトークンを優先するため、`C13` は `C(13)` です。`C79`・`C69` は拒否し、
`C7(9)`・`C6(9)` と書きます。最後の括弧には任意の extension を追加でき、
`C7(13)`、`Csus4(7)`、`C7sus4(9,13)` が有効です。
`C(7)sus4`・`C7(9)(13)` は無効です。分母は最後に `C7sus4(13)/G` のように置きます。

`M7`・`M9`・`M11`・`M13` はそれぞれ1つの extension であり、コード種別の `M` と数字へ
分割しません。`CM7` は `C(M7)` と同じ detailed になり、既存の `CM(7)` は従来どおり
Major のコード本体に `7` を指定する表記です。`CmM7`・`CaugM7` も同じ規則を使います。
`Cdim7` は `Cdim(7)` と同じ detailed を保存し、実音の解釈は行いません。

音名直後の `#`・`b` はルートの変化記号を優先します。`C#5` は `C#(5)`、`Cb5` は `Cb(5)` です。
C の5度を変化させる場合は `C(#5)`・`C(b5)` と書きます。
`omit5` は5度の省略指定です。`omit1`・`omit3`・`no3` は受理しません。
`C9` に `7` を自動追加することはありません。`C7#5omit5` などの音楽的な矛盾も検証せず保持します。

内部の拡張指定の順序は次のとおりです。plain の順序や enum の宣言順とは独立しています。

<!-- extension-order:start -->
```txt
1, 2, 3, 4, 5, 6, 7, M7, 9, M9, 11, M11, 13, M13,
sus2, sus4, b3, b5, #5, b6, b9, #9, b11, #11, b13, #13,
add9, add11, add13, omit5, o
```
<!-- extension-order:end -->

警告は並べ替え前に元の入力順で判定します。`C7(7)` は括弧内の `7` に警告が付き、
AST には両方の値を保持します。省略記法はコードと分母だけに適用し、key や `?`・`_`・`%` には適用しません。

`1` は `C(1)` のように、ルート単音を意図する表記に使えます。
parser はこの指定を `extensions` に保存し、コード本体の種別は保持します。
構成音の算出や extension の組み合わせの音楽的な検証は行わず、実音の解釈は利用側に委ねます。

有効な例：

```txt

C#
C(1)
C(7)
Cm(7)
C(M7)
C(7,9)
C(b5,7)
C(add9)
C(sus4)
Cm(o)
C(7)/E
```

追加で受理する省略記法の例：

```txt

C7
Cm7
CM7
C9
Cadd9
Csus4
Csus4(7)
Cm7b5
Cdim7
Caug7
CaugM7

C7/E
```

`Cmaj7`・`C△7`・`C+7`・`Co`・`Co7`・`Cø7`・`C°7`・`Csus`・`C7sus`・
`C6/9`・`Cadd2`・`Cadd4`・`C7alt`・`Cno3` は非対応です。
既存の括弧内の `o` は引き続き受理しますが、dim の省略記号として括弧外へは展開しません。

## 空の名前付きセクションと原文位置（1.1.1）

コード未入力でも、次の`@section`は別のセクションを開始します。複数の名前を先頭のセクションへまとめません。`@repeat`と、その名前に属する`@same`は同じセクションに保持します。パーサーは参照名を文字列として保持し、参照先の検索・重複の優先順位・識別子の意味はアプリ側で解釈します。

JavaScriptの解析成功結果には、ASTと別に`sectionMetaPositions`を返します。各要素の`sectionIndex`・`metaIndex`は`ast[sectionIndex].metaInfos[metaIndex]`を指し、`position`は`=`の後の値だけの原文範囲です。周囲のASCII空白・タブは含めず、内部空白・Unicode・記号は保持します。位置は元の入力に対するUTF-16 offset（終端はexclusive）で、CRLFは1改行、列とlengthはUnicode scalar単位です。アプリ側の参照診断もこの範囲へ表示でき、正規表現などで原文を再解釈する必要はありません。保存ASTの形は変更しません。
